# Troubleshooting

Common problems and fixes. Still stuck? Open a [bug report](https://github.com/ArcFOSS/pumapanel/issues/new/choose) with logs and your environment.

## Toolchain & install

### `ERR_PNPM_NO_AGENT_SKILLS_DIR` when running `pnpm install`

The workspace declares agent skill directories in `pnpm-workspace.yaml` (`skills.dirs: [.agents/skills, .claude/skills]`), so **do not delete those directories**. If the error persists on an old checkout, `git pull` and re-run `pnpm install`.

### `moon` / `pnpm` / `cargo` not found

- Run `moon setup` to install toolchains through proto.
- Make sure proto's shims are on your `PATH` (follow the install guide at <https://moonrepo.dev>).
- Check versions: `moon --version`, `pnpm --version`, `cargo --version`.

### Rust toolchain mismatch

Versions are pinned (`1.99.0`). If proto isn't selecting the right compiler, run `moon setup` again and confirm with `rustc --version` in the repo. The API uses edition `2024`, so a too-old toolchain will fail to compile.

## Web app

### TypeScript can't find `LayoutProps` (TS2304)

`tsc` consumes route types generated by Next. Run `moon run web:typecheck` (it runs `next typegen` first), or regenerate with a quick `pnpm --filter web dev`.

### Tailwind classes have no effect

Tailwind v4 is wired via the Turbopack rule in `next.config.ts` (`@tailwindcss/turbopack`). Restart `moon run web:dev` after changing `next.config.ts`, and keep the CSS entry at `src/app/globals.css`.

### Port 3000 already in use

`moon run web:dev` refuses to start. Kill the stale process, or change the dev port for one session: `pnpm --filter web exec next dev -p 3005`.

## API

### Port 3001 already in use

The API defaults to `127.0.0.1:3001`. Override per run:

```bash
PORT=3011 HOST=127.0.0.1 moon run api:dev
```

### API not reachable inside containers

The container sets `HOST=0.0.0.0`. If you changed that, other containers cannot connect. Reach the API by the Compose service name: `http://api:3001/health`.

## Containers

### `docker compose up` fails on ports 80/443 (rootless Podman)

Ports below 1024 are unprivileged-only on rootless setups. Use:

```bash
HTTP_PORT=8080 HTTPS_PORT=8443 podman compose up -d
```

### Health checks not running under Podman

Podman's default OCI images drop the Dockerfile `HEALTHCHECK`. The checks are also declared in `compose.yaml`, so `docker compose ps` still shows `(healthy)`. To keep image-level checks for `podman run`, build with `BUILDAH_FORMAT=docker podman build …`.

### SELinux permission denied on bind mounts

`compose.yaml` uses `:Z` suffixes so volumes are relabeled on SELinux hosts. If you mount extra paths yourself, add `:Z` or `:z`.

### Traefik can't get certificates for `example.com` / `localhost`

Let's Encrypt rejects reserved names (expected). Set a real `DOMAIN` that resolves to the host, or switch to the staging CA in `deploy/traefik/traefik.yml` while testing. See [TLS](./deployment/tls.md).

### Both proxies responding / port conflicts

`traefik` and `nginx` profiles are mutually exclusive — enable only one, or one of them will fail to bind `HTTP_PORT`.

### `nginx: [emerg] host not found in upstream "web"`

nginx resolves upstream names at start-up. Run it through Compose (which waits for `web`/`api` to be healthy), or add `--add-host web:127.0.0.1 --add-host api:127.0.0.1` when testing the config standalone.

## CI

### GitHub Actions fails type-checking the web app

Ensure your PR includes the `apps/web/moon.yml` `typecheck` change (it runs `next typegen`). Omit the fix and a pre-`next dev` checkout cannot find `LayoutProps`.

### Image builds are slow

Both jobs use the GitHub Actions cache (`type=gha`) — a second run should be much faster. Rust release builds are the slow part; add `cache-to: mode=max` scope `api` if you customize the workflow.

## Still broken?

Include in your report: OS, `moon --version`, `pnpm --version`, `rustc --version`, engine (Docker/Podman), relevant logs, and the steps from the bug template.
